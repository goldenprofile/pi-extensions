# session-trace

Живой flow-граф сессий pi: ходы агента как карточки, вызовы инструментов как чипы, компакции и смены модели как маркеры на таймлайне. Три формы: расширение pi, автономный CLI и веб-вьюер без зависимостей.

Read-only: только читает session-файлы `~/.pi/agent/sessions/`, ничего не пишет, ничего не отправляет. До переименования внутри этого репозитория расширение называлось pitrace; сессии, записанные старой версией, читаются без ограничений.

## Что рисует

- **Карточка на каждый ход агента**: время, модель, выходные токены, стоимость, длительность
- **Чипы инструментов** под карточкой: имя, сводка аргументов, длительность, `✓ / ✗ / ⠿ running`
- **Превью thinking и ответа** внутри карточки
- **Маркеры таймлайна**: смена модели `⚙`, уровень thinking `✦`, компакция `↻`, ветка `⑂`, метки `⚑`, пользовательские `!`-команды `$`
- **Карточки субагентов** (см. [Субагенты](#субагенты)) со ссылкой на их граф
- Итоги сессии в шапке: токены, стоимость, бейдж LIVE/replay

## Три формы

| Форма | Что | Как |
|---|---|---|
| **Расширение pi** | `/trace` внутри pi: live-слежение за текущей сессией + replay любой другой | грузится из `pi.extensions` этого репозитория |
| **CLI** | терминальный вьюер всех сессий всех проектов, включая запущенные прямо сейчас | `npm run trace` (см. ниже) |
| **Веб** | граф, таймлайн-стрип, воспроизведение до 128× | `/trace-web` в pi или `npm run trace:web` — браузер откроется сам; либо открыть `web/index.html` и перетащить `.jsonl` (без сервера, `file://`) |

## Команда в pi

```
/trace              текущая сессия, follow за живым хвостом
/trace <file.jsonl> replay любой сессии в темпе её timestamp'ов (×8 по умолчанию)
```

Аргумент автодополняется списком сессий проекта (последние 20).

| Клавиша | Действие |
|---|---|
| `↑↓ PgUp PgDn Home End` | скролл (возврат вниз включает follow) |
| `f` | follow за живым хвостом |
| `/` | фильтр по подстроке (чипы, превью, команды) |
| `n` / `N` | следующее / предыдущее совпадение (по кругу; без фильтра — соседний элемент таймлайна) |
| `e` | только ошибки |
| `m` | сводка по моделям: ходы, токены, стоимость |
| `esc` | сброс фильтров, затем закрытие |
| `q` / `Ctrl+C` | закрыть |

В replay дополнительно: `space` пауза · `←→` перемотка ±5с · `+/-` скорость · `l` в конец (и follow растущего файла) · `r` сначала.

Веб: двухколоночный сплит — слева граф на всю высоту (сетка ходов с переносами + чипы активного хода) и под ним стрип-таймлайн с цветными тиками (user / assistant / результаты инструментов / ошибки / компакция) и перетаскиваемым плейхедом, справа — лента карточек; на узких экранах (<880px) колонки складываются в стопку. Клики по узлам графа и карточкам переходят к ходу. Страница открыта через сервер — она сама подтягивает дозапись сессии каждые 2с (live-режим); хэш `#end` открывает сессию сразу с хвоста (реплей по умолчанию стоит в начале).

Раскладка: левая колонка (граф) 60%, правая (лента карточек) 40%, лента — во всю ширину своей колонки.

Зум графа: колесо мыши над канвасом (55–260%, индикатор в углу), двойной клик — сброс зума и выбора.

Клик по узлу T# **не отматывает плейхед**: узел выбирается (кольцо + центрирование окна графа на нём), лента скроллится к карточке хода и подсвечивает её. Плейхед и live-follow сессии не трогаются; клик мимо узлов снимает выбор. Лента приклеена к хвосту, пока пользователь не уйдёт скроллом вверх (или не выберет узел) — возврат к низу возвращает приклеивание; фильтр понимает номера `T12`.

Кнопка **● N** в хедере — живые task_batch-воркеры (глобальный running-индекс из subagents, эндпоинт `/workers`, опрос раз в 5с): клик по карточке переключает вьюер на сессию воркера (через `POST /load`) и открывает её с хвоста. Без subagents-расширения кнопка не появляется.

## Веб из pi и из консоли

```
/trace-web              в браузере: текущая сессия
/trace-web <file.jsonl> в браузере: любая другая сессия
```

Команда поднимает локальный сервер (`web/serve.ts`, слушает только 127.0.0.1) отдельным процессом, открывает браузер и останавливает сервер при закрытии сессии pi. Повторный вызов не плодит серверы: если порт занят своим же экземпляром, он просто переключает файл и открывает вкладку.

Из консоли:

```bash
npm run trace:web                    # самая свежая сессия на машине
npm run trace:web -- --file session.jsonl
npm run trace:web -- --port 9000 --no-open   # без автозапуска браузера
node extensions/session-trace/web/serve.ts   # то же самое напрямую
```

Страница работает и совсем без сервера: откройте `web/index.html` (можно с `file://`) и перетащите `.jsonl` — но тогда автозагрузку и живой хвост сервер не обеспечит.

## CLI без pi

```bash
npm run trace:list        # таблица всех сессий всех проектов
npm run trace             # интерактивный выбор → live-follow
node extensions/session-trace/cli.ts 3          # открыть №3 из списка
node extensions/session-trace/cli.ts -r 3       # replay с начала (×8)
node extensions/session-trace/cli.ts file.jsonl # конкретный файл
```

Требует Node ≥ 22.18 и установленных зависимостей репозитория (`npm install` — подтянет peer `@earendil-works/pi-tui`).

## Смоук-рендер без TTY

```bash
node extensions/session-trace/test/render.ts <session.jsonl> [rows] [--keys=...]
#   --keys="m"          сводка по моделям
#   --keys="/edit\r"    фильтр по подстроке
#   PI_TRACE_MODE=replay — режим replay
```

## Субагенты

session-trace умеет показывать субагентов: дочерние карточки строятся из custom-записей `session-trace:subagents`, которые автоматически пишет наше расширение [subagents](../subagents/) — оба его инструмента (панельный `subagent` и headless `task_batch`). Транскрипты детей лежат в `~/.pi/agent/sessions/subagents/`, карточки ведут на `/trace <child-session>`. Записи под старым именем `pitrace:subagents` тоже распознаются. Подробности — в [docs/subagents.md](docs/subagents.md).

## Как устроено

pi пишет JSONL-транскрипт каждой сессии в `~/.pi/agent/sessions/<munged-cwd>/` (формат v3: дерево записей с `id`/`parentId`, компакции, итоги веток). session-trace читает файл инкрементально, нормализует записи в ходы / чипы / маркеры и рисует их: в процессе pi через Extension API, отдельным терминалом через [pi-tui](https://www.npmjs.com/package/@earendil-works/pi-tui) или в браузере без единой зависимости.

- `session.ts` — чистый разбор JSONL в ленту элементов (без зависимостей)
- `graph.ts` — TUI-компонент (`TraceView`): live/replay, фильтры, мини-карта
- `cli.ts` — автономный вьюер на `ProcessTerminal`/`TuiAltScreen` из pi-tui
- `web/` — браузерный вьюер на чистом JS; `web/serve.ts` — локальный сервер для него же (статика + файл сессии по `/session.jsonl`)
