# session-recall

Полнотекстовый поиск по всем сессиям pi всех проектов на машине. Отвечает на вопрос «как я это чинил месяц назад»: `/resume` показывает только текущий проект и не ищет по содержимому.

Читает `~/.pi/agent/sessions/**/*.jsonl` (или `$PI_CODING_AGENT_DIR/sessions`). Ничего не пишет. Текущая сессия из поиска исключена.

## Команда в pi

```
/recall wezterm plugin                все слова в одном сообщении
/recall "oldText not found"           точная фраза
/recall migration role:user           только мои промпты
/recall alembic tool:edit             только результаты инструмента edit
/recall docker project:mediahub       только проект
/recall                               запрос через диалог ввода
```

Фильтры: `role:user|assistant|tool|custom|summary`, `project:<подстрока имени или пути>`, `tool:<имя инструмента>`.

Результаты отсортированы по дате, новые сверху, до 50 штук. Enter на результате открывает меню:

| Действие | Что делает |
|---|---|
| Show full message | сообщение целиком в прокручиваемом виде с подсветкой |
| Insert snippet into editor | вставляет текст сообщения в редактор с пометкой об источнике, чтобы передать модели |
| Switch to that session | переключает pi на ту сессию через `switchSession` |

## CLI без pi

```bash
node extensions/session-recall/cli.ts wezterm plugin
node extensions/session-recall/cli.ts "oldText not found" role:tool --full
node extensions/session-recall/cli.ts docker --json --limit 5
```

Требует Node 22.18 или новее, зависимостей нет.

## Что индексируется

Одно сообщение это одна единица поиска: промпты пользователя, текст ответов модели вместе с вызовами инструментов и их аргументами (полезно искать по oldText в edit), результаты инструментов, custom-сообщения расширений, итоги компакций и веток. Размышления модели не индексируются.

Индекс живёт в памяти расширения и перечитывает только новые и изменённые файлы по mtime и размеру.

## Оговорки

- Поиск по подстроке без учёта регистра, без морфологии и без нечёткости. Многословный запрос требует все слова в одном сообщении.
- Большие результаты инструментов индексируются целиком, поэтому на сотнях сессий первый поиск может занять секунды, повторные быстрые.
